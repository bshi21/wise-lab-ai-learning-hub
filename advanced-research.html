PATH 02 · ADVANCED AI RESEARCH

从“会用”走向可解释、可评估的系统。

面向构建 AI、agentic 或数据密集型研究系统的成员。这里提供能力地图和外部学习入口，而不是一个特定应用的演示，亦不会把 RAG 或数据连接简化为“接上就能用”。

建议人群：博后 · AI 研究人员 · 技术型研究生前置条件：Python / Git / LLM 基础模式：课程 · 文档 · 技术参考

START WITH THE OUTCOME

完成后，你应能做到：

  • 把 agent 系统拆成任务、状态、工具、权限和人工审核点。
  • 针对 RAG 或连接器方案说明数据来源、访问控制、检索策略、评估与时效性。
  • 用测试、日志、成本控制和回滚思维评估系统是否可以进入真实环境。

CAPABILITY MAP

七块能力，不是一套框架。

先把系统边界、数据和评估说清楚，再选择模型、框架或部署方式。

查看精选资源 ↓
A

Software & LLM foundations

Python、Git、软件质量、API、结构化输出、token/成本/延迟意识及模型选择。没有这些基础，后续 agent 设计很难验证。

学习：scikit-learn MOOC ↗
B

Agent architecture

任务拆解、工具调用、状态、规划、交接、有限自主性与失败模式。系统应明确什么能做、什么不能做、在哪一步必须停下来。

学习：Agents Course ↗
C

Skill authoring & tool interfaces

当重复工作已经有清晰边界时，才学习编写 skill：将 instructions 与 tools 分离，定义输入输出、权限和密钥，并理解 MCP/API 的作用。优先只读与最小权限，避免把开放式工具当成默认能力。

学习：Build skills ↗
D

Context engineering & memory

上下文选择、压缩、检索、会话状态、长期记忆、污染与过期。记忆不是越多越好；必须说明它来自哪里、何时失效、如何被审查。

学习：Context Engineering Course ↗
E

RAG & connected knowledge

摄取、chunking、metadata、检索、引文、access control、评估与 freshness。RAG 是连接受控知识源的设计问题，不是上传文件后的自动真相机器。

学习：Happy-LLM ↗
F

Evaluation & assurance

任务测试集、tool-use tests、安全边界、审计日志、可观测性、人工审批和回归测试。评估应在演示前开始，并覆盖失败与拒绝执行的情况。

参考：AgentGuide ↗
G

Deployment & operations

身份、secrets、版本、日志、监控、成本控制、回滚与生命周期管理。研究原型和可操作系统之间，需要清晰的责任与运行边界。

参考：Copilot Connectors overview ↗

MINIMUM COMPLETION STANDARD

写出一页 Agent Design Brief。

它不是展示酷炫 demo，而是让同行能理解并审查你的系统边界。每个进阶学习者都应能完成这个最小说明。

  • 目的与任务成功条件
  • 输入与数据分类
  • 可调用的工具及权限
  • context strategy 与 memory policy
  • RAG/连接器的访问控制
  • 评估与回归测试方法
  • 人工批准点与审计记录
  • 运行限制、成本控制与回滚方式

DATA CONNECTIONS ARE A DESIGN DECISION

连接数据前，先选择“索引”还是“实时读取”。

例如，Copilot connector 的 synced 模式会摄取和索引内容；federated 模式以 MCP 实时读取且可保持数据在来源系统中。两者都需要确认身份、权限、机构配置和适用许可。把数据范围、接收人和人工审阅写进设计，而不是留给工具默认值。
